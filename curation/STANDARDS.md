# Authoring and revision standards

An owner request to work on a course is sufficient to commission an isolated
candidate. Catalogue membership is inventory, not an editing permission switch.
Retained drafts may be revised before catalogue admission or publication.

Use README.md for the design, runtime dependency, quiz and learner-storage
contracts. Preserve each course's visual identity, diagrams and interactive
examples. A behaviour repair preserves lesson and quiz content; identify content
changes separately for factual review.

For every quiz repair, verify selection without disclosure, submit-all grading,
the nearest achievable scores below and at the 60% boundary, persisted choices,
score and feedback after reload, and explicit blank retakes. On failure, mark
incorrect selections and explain correct selections without revealing missed
answers. Previously earned completion survives failures and retakes.

Preserve the existing storage key and shape, unrelated module attempts, lab and
theme preferences, and navigation state. Do not invent historical scores. Check
all modules at desktop and narrow widths, navigation, diagrams, browser errors
and compatibility with the hub's progress reader.

Candidates must contain the real learner controls needed for browser validation;
never add hidden alternate controls just to satisfy checks. If a source format
needs an adapter, report that specific missing capability. Do not reskin a course
or discard features to force it into a template.

Treat each revision as a new candidate tied to its exact source version. Keep
prior drafts and evidence. Passing browser checks does not establish factual
accuracy or publication. Promotion into the catalogue, hub changes and deployment
are separate publication work.
